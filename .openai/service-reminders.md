# Service records and event-driven reminders

The owner-private Site keeps a durable D1 register of service items and historical work records. The unified Service work register and each item's history use the same data. No dates or mileage are fabricated; past work is entered manually. Records can be edited or deleted. A later insertion with an older performed date does not reset the current interval: calculations use the latest performed date.

The latest oil replacement establishes the date and mileage baseline; the oil filter follows the same record. Current mileage comes from the latest dated fuel entry that contains mileage. A new fuel record or edit updates the UI immediately from the authoritative response and recalculates reminders on the server after the response via after(). A skipped fuel mileage leaves the last known mileage in use. Every replacement/inspection starts that item's next interval; the history remains intact.

Oil recommends replacement at 10000 km, reaches its limit at 12000 km or 12 calendar months, whichever arrives first. Cabin filter recommends 12 months and limits 24. Air filter uses 24 months. Wipers use 24 months after installation, then 12 months after each inspection; replacement restarts 24 months. Tires and brakes use 6 months after installation/inspection. Fuel filter has no invented interval. Custom services support optional calendar and mileage limits.

There is no daily task, cron job, polling timer or scheduled check. Status is calculated when records are read/rendered; calendar state also refreshes when the app becomes visible. Notification dispatch runs after opening with granted permission and after fuel/service writes. It respects each item's reminder checkbox and sends one encrypted Web Push per enabled service, device, record cycle and severity. Expired subscriptions are removed; unsuccessful push requests can retry at the next event. Unknown baselines do not produce fabricated warnings.

VAPID_PUBLIC_KEY and VAPID_PRIVATE_KEY live in Sites runtime variables; only the private key is secret. Subscription requires the user's explicit button click. On iPhone use the Home Screen app with iOS 16.4+. The existing service worker displays each push and opens Service when tapped. The private POST /api/service/dispatch is the common event writer, protected by owner-private Sites access. Do not expose it publicly without explicit authorization.
